# M7.5: Cancellation

**Status:** ✅ Completed
**Date:** 2026-08-07
**Depends on:** M6 (AgentSession), M7 (permission modes)

Numbered 7.5 because this closes debt from M6's stated scope rather than
opening a new milestone. M6 shipped `AgentSession.cancel()` and an
`AbortController`, but nothing reached `fetch` and no key handler called it —
the method existed and did nothing.

---

## Objective

Make Ctrl-C interrupt an in-flight agent turn, leaving the session usable
afterwards. Without it a 20-round tool loop that goes wrong can only be
escaped by killing the process.

---

## Scope

### In scope
- `AbortSignal` threaded from `AgentSession` through `ModelRequest` to `fetch`
- Abort checks at both loop boundaries: before each model call, and after each
  batch of tools
- `AbortError` translated into a typed `ModelRequestAbortedError`
- Ctrl-C bound in the TUI, cancelling when an agent turn is running and exiting
  otherwise
- Conversation history rolled back on cancel so the next turn is still valid

### Out of scope
- Cancelling a running command (`commands/runner.ts` has a timeout but no
  cancel; Ctrl-C deliberately exits instead of falsely claiming a cancel)
- Cancelling `summarizeCommandResult`
- Cancelling a partially applied edit — `edits/apply.ts` is atomic by design and
  must not be interruptible mid-commit

---

## Implementation

### 1. Signal plumbing — `src/model/types.ts`, `src/model/openai-compatible.ts`

`ModelRequest` gains an optional `signal?: AbortSignal`. The client forwards it
to `fetch`, returns early if the signal is already aborted, and converts
`fetch`'s `AbortError` into `ModelRequestAbortedError` so callers can
distinguish a deliberate cancel from a network failure. Non-abort errors pass
through untouched.

### 2. Loop integration — `src/agent/agent.ts`

`ask()` creates a controller per turn and checks `signal.aborted` at two points:
before each model call, and after each batch of tool executions. The second
check matters because tools run locally and fast; without it a cancel during
tool execution would still trigger another model round.

`cancel()` no longer nulls the controller. Nulling it meant an abort could race
with the running `ask()` and be lost; the `finally` block now clears it, and
only if this turn still owns it, so a later turn's controller is never clobbered.

**History rollback.** This was the part that made cancellation actually usable.
Without it, a cancel mid-tool-round leaves `messages` ending in an assistant
message carrying `tool_calls` with no matching tool results — a shape every
OpenAI-compatible provider rejects. The session would be permanently broken
after one cancel. `ask()` now records the message count and `repoMapSent` flag
on entry and restores both when a turn aborts.

Also removed `createInitialMessages()`, dead since the M6 class refactor, and
replaced it with `createRepoMapMessage()` which `ask()` actually calls.

### 3. Ctrl-C — `src/tui/interrupt.ts`, `src/tui/App.tsx`, `src/cli/commands.ts`

Ink exits the process on Ctrl-C by default, so the handler alone would have
cancelled the agent and quit in the same keystroke. `render()` now passes
`exitOnCtrlC: false` and `App` owns the key entirely, calling `useApp().exit()`
for the idle case.

The decision lives in `interrupt.ts:getInterruptAction()`, a pure function
returning `ignore | cancel-agent | exit`, following the same convention as
`command-confirmation.ts` so it is testable without rendering Ink.

`App` tracks `agentBusy` separately from `busy`. `busy` is also true while a
command runs or an edit applies, and `cancel()` is a no-op then — so keying off
`busy` would have printed "已取消当前请求" while cancelling nothing and not
exiting either. `agentBusy` is true only around `agentRef.current.ask()`.

A cancelled turn returns early from `handleSubmit`'s catch so it does not also
render as "请求失败".

## Tests

| File | Tests | Covers |
|---|---|---|
| `tests/agent/cancel.test.ts` | 6 | signal is live and rejects on abort; cancel between tool rounds makes no further model call; already-aborted signal; idle cancel is a no-op; **history stays valid for the next turn**; fresh signal per turn |
| `tests/model/openai-compatible.test.ts` | +4 | signal forwarded to `fetch`; `AbortError` → `ModelRequestAbortedError`; no `fetch` call when pre-aborted; non-abort errors unchanged |
| `tests/tui/interrupt.test.ts` | 6 | non-Ctrl-C ignored; cancel only during an agent turn; exit when idle, during a command, or before the model is configured |

The cancel mocks return a promise that settles *only* on abort, mirroring a real
in-flight `fetch`. An earlier draft used timers and `setImmediate`, which raced:
the mock finished before the test could cancel, so `ask()` had already cleared
the controller. Those tests failed for the wrong reason and were rewritten.

**The history-rollback test was verified to fail without the fix** — the
rollback was temporarily removed and only that test broke, confirming it tests
the behavior rather than passing incidentally.

**Suite: 147/154.** Baseline before this work was 131/138: +16 tests, 0 new
failures. The 7 failures are pre-existing and environmental, unchanged:
3 × `EPERM: symlink` (Windows needs admin/Developer Mode), 3 × POSIX file-mode
bits on NTFS, 2 × path separators in `search-text`.

**Not verified: the actual keystroke.** `getInterruptAction` is unit-tested and
the wiring typechecks, but no automated test presses Ctrl-C in a live Ink
session — that needs a pty or `ink-testing-library`, neither of which is a
dependency. The `exitOnCtrlC: false` change in particular is only verified by
reading Ink's API. This should be smoke-tested by hand against a real model
before being relied on.
